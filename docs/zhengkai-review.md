# 正楷自动初审：Y 键试验

## 目标与边界

把「反查例字 → 打开字根图解 → 高亮 → 查笔顺 → 抽笔」变成离线数据处理。
人工只需要对照黑体、当前正楷与候选，选择保留或 A/B/C。数值评分不是正确率，
不要求正楷模仿黑体粗细，也不自动删除疑似重复字根或新增字根。

- 生成报告不修改字体，也不把任何候选标为人工通过。
- 正楷确认独立保存，不读取文楷的 `confirmed` 作为正楷确认。
- 既有 `DERIVED` 人工取法保留，覆盖需另行显式允许。
- 这轮只生成 Y 键报告；通用入口接受 `--key`，便于试验成功后复用。

## 生成与审阅

需要先有 `public/data/` 与现有 `public/fonts/zhengkai-roots.woff2`。
Python 依赖沿用 `scripts/requirements-font.txt`，WOFF2 构建还需 `brotli`。

```bash
npm run review:zheng:y
# 自定义比较源字/取笔组合数（默认每根最多 48 个）：
npm run review:zheng -- --key y --chars 80
```

输出 `reports/zhengkai-review/y.html` 与 `y.json`。HTML 内嵌数据、SVG、CSS 与 JS，
双击即可打开，不需要网络或启动主页。`reports/` 沿用项目的 gitignore，不提交生成产物。

审阅页默认按缺失、结构差异、一般对照排列；可切到原编号顺序、按编号搜索或只看缺字。
每个候选附有源字（蓝色为目标笔画，灰色为其余笔画）、一开始就已确定的笔序，以及字体位置预览。
「适配原槽位」只做等比缩放与平移，不压扁或改写笔画；取消则使用源字中的原位置。

操作：

- **保留当前**：人工确认现有正楷；正楷缺失时不可选。
- **A/B/C**：人工选择某个 MMH 源字的指定笔画。
- **都不对 / 待补**：保留疑难项与备注，不写入正式字体。
- **清除判断**：只清除这行浏览器判断，不删除项目映射。
- 键盘 `1/2/3` 选候选、`0` 保留、`X` 待补，`J/K` 或上下方向键移动行。
  在输入框里打字不触发快捷键。
- 判断存在该浏览器的 localStorage（按按键和报告指纹隔离），建议随时下载 JSON 备份。
- 可导入同一报告导出的 JSON；过期报告或候选编号不匹配时拒绝导入。

## 批量应用

页面的选择只保存浏览器判断。下载「判断 JSON」后：

```bash
# 默认 dry-run，只列出将要保留/替换的字根。
npm run review:zheng:apply -- /path/zhengkai-review-y.json

# 明确写入人工确认表（仍不直接构建字体）。
npm run review:zheng:apply -- /path/zhengkai-review-y.json --write

# 构建字体，并重新生成最终字体对照。
npm run font:zhengkai
npm run review:zheng:y

# 原来的三体字根表如需刷新：
npm run roots:key
```

仅人工 `candidate` 与 `keep` 会进入 `scripts/zhengkai-roots-review.json`。
`pending`、`defer` 和备注不构成确认。应用先完整校验全部判断，再原子写入，
不会因文件后半段有无效判断而应用前半段。未涉及的字根和文楷映射保持不变。

已有人工正楷记录默认保护，确需改动时在同一命令明确加 `--overwrite-confirmed`。
重新生成页后，本地旧判断会被识别为过期；不要反复套用旧 JSON。

报告指纹覆盖输入源数据、当前字体和生成算法。MMH 源字、字根数据、字体或脚本变化时，
应用会拒绝旧报告，要求重新生成并确认。正式确认表还逐条保护同根记录，防止覆盖其他操作。

## 数据与候选逻辑

1. 按 `roots.json` 的键归属枚举非识别码、未删除字根，编号保持原 PUA。
2. 反查 `public/data/c/*.json` 的 `r`，从同位置 `seg` 提取 MMH 笔画。
   同字重复字根分别提取，不连续索引原样保留。
3. 优先原始 `source`、单字根整字 `whole`，其次 `exact`；近似结果 `approx` 降权。
   没有有效拆分时才有限搜索连续取笔，并醒目标为人工核对。
4. 以双向容差 F1 与结构参考排序，可靠例字的主要笔画数量作结构提示。
   归一化字形近重复的候选分组，最多展示 3 个不同代表，不把不同笔数合并。
5. 预览与真正造字使用相同的 `build_glyph()`、`fit_to_hei()`；选定后码位不变。
6. 黑体近重复仅提示编号，不自动合并。

新增变体使用 `kai-roots-extras.json` 的 `variant_of` 指向原根；审阅页注明黑体参考编号，

重建原字根表时，若文楷源字体不可用，会复用已有报告中未变化的文楷增补轮廓；
