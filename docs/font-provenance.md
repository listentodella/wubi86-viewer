# 字根字体来源与许可

## `data-src/黑体字根.ttf`

- 字体名：黑体字根（Regular），Version 1.00，2022-05-12。
- 结构：690 个字形、687 个码位，其中 671 个 PUA（E000 起），仅 10 个 Unicode（龰 龴 龵 龶 龷 龸 龹 龺 龻）。
- name 表只有 family/version，没有 copyright、license、designer、vendor URL；OS/2 vendID 为 `MS  `。
- 开源输入法项目 `huanfeng/WindInput` 的 `NOTICE.md` 明确写道：`HeiTiZiGen.ttf`「来源不详，无授权信息」；`qwertyyb/Fire` 也直接打包了同一文件。
- 结论：**不是有明确开源许可的字体**，来源与授权不明。仓库目前把它作为 `data-src` 数据源分发，存在许可风险；长期应替换。

## 楷体字根字体 `data-src/文楷字根.ttf`

- 在 GitHub 上检索 `楷体字根`、`KaiTiZiGen`、`五笔字根 楷体` 等，没有找到开源的楷体字根 TTF；书中字根图
  （PDF 第 20 页）没有嵌入字体，全部是矢量轮廓，也无法直接抽出楷体字根字体。
- 因此本仓库用 **LXGW WenKai（霞鹜文楷，SIL OFL 1.1）** 生成了楷体字根字体，做法见 `scripts/build-kai-roots-font.py`：
  1. 以 `黑体字根.ttf` 为版式基准：码位（677 个 PUA + 9FB0–9FBB 九个 Unicode）、字形数、advance width 全部照抄，
     两颗字体可直接互换；
  2. 每个 PUA 码位映射到一个汉字，再用文楷该字的轮廓重绘：1000→2048 缩放到新 em，按黑体字根的包围盒中心对齐，
     并按**墨量（填充面积）**比做 0.75–1.7 限幅缩放——用墨量而不是包围盒，是因为「四个点」这类稀疏字形
     包围盒很大但墨很少，按包围盒放大会把它撑到 5 倍重；现在全字体的楷/黑墨量比中位 1.00、p95 1.01；
  3. 有两类字形不是汉字，按黑体原形的**各笔画包围盒**逐个合成：15 个识别码字形（外框 + 1~3 个末笔标记，
     用 `囗` + `一/丨/丿/丶/乙`），以及「若干独立笔画」型字根（如 鬯/鹵/滷 的四点，用 `{"compose": "丶"}`）；
  4. 映射来源分三档：`roots.json` 的 138 个数据锚点与 `scripts/root-names.json` 的单字字根名直接采信，
     其余按轮廓相似度自动匹配；逐字来源、分数与备选见 `docs/kai-roots-map.md`，改 `scripts/kai-roots-map.json` 后重跑即可修正。
- 轮廓匹配质量：在 138 个锚点上做同键候选的留一验证，top-1 为 132/137（96.4%）；自动匹配中置信度低的条目在报告里列出，
  建议对照书图核对。识别码字形属于合成结果，未参与该验证。
- **结构校验**（`kai_font.struct_sig` / `struct_mismatch`）：对黑体原形和候选字各自算「墨块数、孔洞数、笔画端点数、
  交叉数」，墨块/孔洞差太多就判定"结构上不可能是同一个字"并排除该候选（`--restructure` 可对已有非人工条目重选）。
  像素 IoU 对"多一笔少一笔"不敏感（米 vs 四个点），结构校验正好补这一点；在 137 个锚点上零误报。
- 新字体保留 9 个 Unicode 码位原名（龰 龴 龵 龶 龷 龸 龹 龺 龻），`cmap`/`hmtx`/`post` 与黑体版逐项对齐；
  黑体版自带的 TrueType 指令（`fpgm`/`prep`/`cvt `）被去掉——那些指令只对原轮廓有效。
  度量沿用黑体版（upem 2048、hhea 1705/-287、OS/2 typo 1434/-410），`fsType` 改为 0。

## 核对流程

- `npm run review:kai` 生成 `reports/kai-roots/文楷字根-核对.html` 与 `.tsv`：逐行列出黑体原形、当前楷体、
  6 个备选汉字（文楷字形）与形似度。**行号固定为 PUA 码位升序**（与 `docs/kai-roots-map.md` 逐行一致，
  修正后不会改号）；优先级用页面筛选与「排序 → 形似度低→高」，已人工确认的行标记「人工」并默认隐藏。
- 页面每行有「对 / 错」按钮与「答案 / 备注」输入框，核对完点「复制结果」导出
  `pua→你的答案→备注` 三列；判定存浏览器 localStorage，刷新不丢。人工核对过的条目，置信度按**人工**显示。
- `scripts/apply-kai-roots-review.py` 把表格里填的答案写回 `scripts/kai-roots-map.json`，再跑
  `npm run font:kai` 重建。答案支持：候选编号、汉字、`无`（留空）、`黑体`（保留黑体轮廓）、`P3`（部件字表编号）。
- 非成字字根（书中没有对应汉字）优先在部件字表里挑近似部件（`scripts/kai-roots-palette.json`，文楷全部覆盖）；
  实在没有就填 `无` 留空，或填 `黑体` 保留原轮廓——后者会让字体混入授权不明的黑体轮廓，报告里会标注。
- 另外支持 `{"ch": "龶", "raise_bottom": 16}`：把该字**最下方一条宽笔画**局部剪切抬成提（右端上扬），
  用于「青字头」压在月/日上的楷书写法；只动底部笔画带，其余笔画不变。
- 映射表条目支持四种写法：`"龶"`、`""`（确认留空）、`{"ch": "", "keep_hei": true, "note": "…"}`、
  `{"compose": "丶", "note": "…"}`（按黑体每个笔画的框逐个合成——适合「四个点」这种非成字字根）。

## 许可

- `data-src/文楷字根.ttf` 的轮廓来自 LXGW WenKai，必须继续以 SIL OFL 1.1 分发，且**不得使用保留字体名**
  `霞鹜`、`霞鶩`、`落霞孤鹜`、`落霞孤鶩`、`LXGW`。本字体命名为「文楷字根」（PostScript 名 `WenKaiZiGen-Regular`），
  版权与许可声明写入 `name` 表，许可全文随字体放在 `data-src/文楷字根-OFL.txt`。
- 码位分配与字宽沿用 `黑体字根.ttf`（该字体授权不明）：写进新字体的是 PUA 码位、advance width 与包围盒测量值，
  不含其轮廓数据。

## 本站现状

- `roots.json` 的 `p` 是构建时从 `黑体字根.ttf` 提取的 SVG 路径；页面不加载 TTF，但路径是字体的衍生数据。
- `public/fonts/lxgw-wenkai-roots.woff2` 是 LXGW WenKai 的子集（SIL OFL 1.1），用于命名根的楷体显示；许可文件同目录。
- 页面上的「楷体 / 黑体」切换目前只影响 138 个命名字根（走 woff2 子集）；整份字根表要切换，可直接改用
  `data-src/文楷字根.ttf`——码位与黑体版一致，数据无需改动。

## 字根表（可选的第二支字体）

- `data-src/文楷字根表.ttf`：同样来自文楷轮廓，但 **cmap 按书序重编**（U+E000 起，11 G → 55 X），
  用来直接渲染字根表；它与 `文楷字根.ttf` 互不影响（后者仍是 `黑体字根.ttf` 的等码位替换件）。
- 生成：`npm run roots:key`（先 `npm run font:kai`）。脚本按 `public/data/roots.json` 的键归属分组，
  键内先按口诀出现位置、其余按 PUA 升序；`id == 1` 的槽位是识别码格，单独标注并排在键末。
- 评审否掉（`rejected`）的行现在**留空**：此前它们仍会画出被否的候选字（例如 U+E021 画的是「丁」），
  已在 `map_value()` 修正。留空行在 `reports/roots-by-key/index.html` 里显示为虚线问号格，便于继续判定。
- 同一脚本输出 `docs/roots-by-key.md`（清单，含每个槽位在字根表字体里的码位）与
  `reports/roots-by-key/roots-by-key.json`；许可随字体放在 `data-src/文楷字根表-OFL.txt`，命名不含保留字体名。
- 该字体的字形名仍是原 PUA 名（如 `uniE002`），只有 cmap 按书序重编；引用时请按码位，不要按字形名推断。
- 新增字根（数据里没有槽位、但原书里有的，如 G 键的「王旁」）写在 `scripts/kai-roots-extras.json`：
  它只进字根表这一支（`文楷字根表.ttf` 会为此多一个字形与码位），**不动** `文楷字根.ttf` 的等码位布局；
  字段 `ch/ref/scale/squeeze/raise_bottom/after` 分别表示汉字、参考槽位、整体缩放、横向压窄、底横提笔、插入位置；
  `ch` 留空表示还没有对得上的单字（文楷先不画，只靠正楷抽笔画字形）。
- 行序：`scripts/kai-roots-map.json` 里的 `at` 可显式指定口诀锚点（汉字 = 口诀里该字的位置，`-1` = 排到键末段），
  避免改了 `label` 之后行序被口诀定位带偏。

## 第三种字形：正楷（Make Me a Hanzi / 文鼎 PL 楷书）

- App 的字形切换现在是三档：**文楷 / 正楷 / 黑体**（`src/lib/root-font.tsx` 的 `RootFontMode`）。
- 正楷字体 `public/fonts/zhengkai-roots.woff2`（159 字，1024 em）由
  `npm run font:zhengkai` 生成：取 `data-src/hanzi-writer-data/<字>.json` 的笔画路径，
  展平后按统一绕向写进 glyf，再转 woff2。
- 同一条命令还产出等码位 TTF `data-src/正楷字根.ttf`：槽位、字形顺序与 advance 宽度都和
  `data-src/黑体字根.ttf` 完全一致（687 cmap / 690 字形 / 2048 em），有正楷的槽位换成正楷字形，
  其余留空，标 `removed` 的槽位也留空——所以可以和 `黑体字根.ttf`、`文楷字根.ttf` 逐槽对比或直接互换。
  `--ttf-out none` 可只出 woff2。
- 覆盖：命名字根 165 个里 159 个有正楷字形；缺的 6 个（〇䒑丆朩龰龷）回落到文楷（font-family 里排在后面）。
- 另用**抽笔画**造了 205 个部件字形（用户指定取法，同样来自 MMH；其中 117 条写在脚本里，
  88 条来自 `scripts/zhengkai-roots-review.json` 的人工确认表），以
  `scripts/build-zhengkai-font.py` 的 `DERIVED` 表为准（码位 → 源字 + 保留的笔序，笔序从 1 起算给用户看）：
  G 键 王旁←环前 4 笔、青字头←青/静前 4 笔、雨字头←雪前 8 笔、提←打第 3 笔；F 键 土旁←坏前 3 笔、
  寸去点←寸前 2 笔、革去廿←革第 5–9 笔；D 键 达去辶←达前 3 笔、倏的犬←倏第 7–10 笔、羊去两点←羊第 3–6 笔、
  羯左去点、套去大、石去口、灰去火、尤去竖弯钩、而上半；S 键 木旁←林前 4 笔、条去夂、哥上半去口；
  A 键 工旁←功前 3 笔、氏后二笔、廿前三笔、升去首笔、车前两笔、切左、牙头、龷、戉头、卄；
  H 键 上（前两笔）、具去八、足去口、虎前四笔、皮前三笔、此左（止）、延二三四笔、矗 11–16 笔（= 且）；
  T 键 撇←生第 2 笔、撇横←币第 1 笔、条字头(夂)←条第 1–3 笔、竹字头←笼前 6 笔、𠂉←医第 2–3 笔、
  余下←荼第 6–10 笔；新增 禾旁←和前 5 笔、攵←獒第 7–10 笔、夂←额第 4–6 笔；
  R 键 丘←丘前 4 笔、勿←勿第 3–4 笔、反←反前 2 笔、看←看前 4 笔、⺧←牛前 3 笔、牜←牧第 2–4 笔，
  新增 气前 2 笔（E910，排在 ⺧ 之后）；
  E 键全面改为抽笔画：且前 4 笔、有 3~6 笔、甬 3~7 笔、象下半（7~11 笔）、
  衣 3~6 笔、派 6~9 笔、辰 5~7 笔、及前 2 笔、豹前 4 笔、豹 5~7 笔、恳 4~6 笔、
  舟去首笔；新增 勇 3~7 笔（E911）、逐 1~7 笔（E912）、遂 4~9 笔（E913）、
  农 3~6 笔（E914）、圜 12~15 笔（E915）、退 4~6 笔（E916）；
  Q 键（用户指定取法）：E123←鑫左下角金、E131←鱼前 7 笔、E0E9←乂、E0ED←凶前 2 笔、
  E0EE←史第 4–5 笔、E12B←无第 3–4 笔、E12C←然前 4 笔、E099←流第 8–10 笔、E125←色前 2 笔、

  E134←乐前 2 笔、E135←卬前 2 笔；新增 鸩 3~4 笔（E918）、顽 3~4 笔（E919），排在 E12B 之后。
  字根表页面的正楷一律**优先取这些抽笔画字形**，没有再按汉字查。
  没有对得上单字的新增字根（如 `E907` 延二三四笔）**文楷先留空**，只显示正楷。
- `DERIVED` 的第三项可选：写一个数字 = 整体纵向平移（字体单位）；写 `{"fit": "e06e"}` =
  把这组笔画等比放进槽位 E06E 的黑体字形框（`fit_to_hei()`），用于原字里只占三分之一宽、
  又坐在下部的部件——例如 `E908`（矗 11–16 笔），照搬会明显偏小偏低。
